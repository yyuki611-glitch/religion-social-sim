# 設計

このリポジトリは2つのパターンを組み合わせている。

- `my-social-agents`：実験ファーストのスクリプト、スイープ、分析。
- `hackathon-singulab`：再利用可能なシミュレーションコア + ドメインパック。

コアエンジンはドメイン非依存に保つ。日本の宗教データ、プロンプト、シナリオ、バリデーションルールは `domain_packs/japan_religion` に置く。

最初のマイルストーンは、以下に答えられるコンパクトなシミュレーション。

- あるイベントパターンのもとで、どの信念が成長するか？
- どのエージェントが改宗・混淆・維持するか？
- その変化の理由として何が記録されるか？
- どのパラメータがスイープに値するか？

## エンジンの力学（v0.2.0）

各ステップで、エージェントごとに全信念の「引力スコア」を計算する。

- **訴求一致**：信念の訴求タグ（practical_benefit, salvation 等）× 本人特性のマッピング（重み 0.50）
- **共同体圧力**：周囲でその信念を持つ人の割合 × 共同体依存（重み 0.35）
- **慣性**：現信仰の強度 × 0.25 + 伝統志向 × 0.10（通常成長は強度 0.90 で頭打ち。鉄壁化を防ぐ）
- **イベント**：権威・噂・共同体シグナル × 対応特性。1ステップごとに 0.92 倍で減衰。scandal 型は噂が反発に働く

最有力の他信念とのギャップが本人の閾値（伝統志向が高いほど高く、新奇開放性が高いほど低い）を3ステップ連続で超え、かつ `conversion_pressure`（不安・救済欲求・実利欲求などの合成値）の確率判定を通ると**改宗**。寛容度 0.65 以上のエージェントは改宗に至らない圧力を**習合**（副次信仰）として取り込む。世代交代イベントは伝統志向と信仰強度を一律に薄める。

全改宗イベントには gap / threshold / openness / 主要因 / 不安値の理由トレースが付く。

## 参考リポジトリ分析からの取り込み方針（2026-06-05）

- `my-social-agents` から：**実験ファースト**（パラメータスイープ + 全実験共通スキーマの集計、決定的物理と LLM 判断の分離、JSONL→グラフ→ビューアの3段階可視化）。スイープは次フェーズで導入する。
- `hackathon-singulab` から：**観測器プロンプト**（エージェントに行動を命令せず「この条件の人物が自然にどう感じ・動いたか」を記録させる）、CLI LLM バックエンド抽象化、TSV ベースのドメインパック。LLM バックエンドは v0.2.0 で導入済み。観測器スタイルのエージェント単位 LLM 判断は次フェーズ候補。
